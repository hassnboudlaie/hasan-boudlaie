# گزارش پیاده‌سازی نقشه راهبرد و هم‌راستایی OKR کیش
تاریخ بررسی: ۲۵ اکتبر ۲۰۲۶ / ۳ آبان ۱۴۰۵

## دامنه
بازطراحی مسیر اصلی `#map` بر مبنای تصویر Perdoo، بدون ساخت بانک جداگانه اهداف یا شاخص‌ها و بدون حذف داده‌های موجود. رابط آموزش در نسخه عملیاتی پنهان مانده است؛ اجزای سازگاری آن هنوز در کد تاریخی حضور دارند.

## پیاده‌سازی و مستندات
- نقشه چهارسطحی: هدف غایی، ارکان راهبردی، اهداف سالانه، اهداف فصلی، در همان ماژول Map.
- دریافت مستقیم از state.strategy، allObjectives، pKpis، pEnsure().people، state.initiatives، state.history، gpEnsure().cycles و pdCadences.
- تشخیص دوره از Cadence و Timeframe ثبت‌شده؛ نمایش سال شمسی، امکان انتخاب سال و نمایش جداگانه اهداف فاقد دوره.
- محاسبه KPI Health تنها برای KPIهای با مقدار جاری و هدف عددی معتبر؛ تفکیک مطلوب، نامطلوب و فاقد داده.
- شمارش اهداف متصل به رکن؛ جلوگیری از اشتباه شمارش KR و Initiatives به جای OKR.
- Badge واحد سازمانی از نام ثبت‌شده تیم و نمایش Avatar مسئول یا حروف آغاز نام؛ پیوند به مشخصات مسئول.
- نمایش وضعیت هدف از داده Check-in معتبر؛ «بدون وضعیت» در صورت نبود گزارش؛ وضعیت مختومه مستقل.
- محاسبه درصد Objective با میانگین ساده KRهای معتبر و پنل شفافیتِ مبنا، هدف، مقدار جاری و سهم هر نتیجه.
- پیوند مستقیم کارت هدف به جزئیات و امکان ویرایش همان هدف؛ نشان دادن تعداد نتایج و ابتکارات مرتبط.
- رنگ‌بندی متنوع، خطوط و اتصالات درختی، اسکرول افقی، Zoom، Drag-to-Pan و Collapse برای شاخه‌های سالانه.
- RTL فارسی و طراحی واکنش‌گرا در CSS؛ دست‌نخورده ماندن منطق ذخیره اصلی.

## تست‌های انجام‌شده
- JavaScript parse در محیط V8: موفق.
- Syntax اسکریپت اصلی HTML: موفق.
- آزمون ساخت HTML برای داده‌های تستی: موفق در ۱۶ مورد؛ شامل سال شمسی، هدف غایی، وضعیت KPI، اهداف سالانه و فصلی، فصل مستقیم زیر رکن، هدف فاقد رکن، تفکیک پیشرفت/سلامت، عدم تولید مقادیر خیالی، لینک‌ها، XSS-escaping، Zoom، Collapse و RTL.
- فایل‌های CSS و JavaScript از GitHub Pages در دسترس هستند؛ Commit مربوط به Index نیز در شاخه اصلی ثبت شده است.
- **انجام نشده / تأیید نشده:** تست End-to-End در مرورگر واقعی، ذخیره و بازیابی چندکاربره و تصویربرداری/مقایسه چیدمان در موبایل و دسکتاپ.

## محدودیت‌های استقرار سازمانی
- `PRACTICE_MODE=true` همچنان فعال است؛ نسخه GitHub Pages نباید به‌عنوان سامانه مرکزی امن سازمانی معرفی شود.
- پایگاه داده سروری، دسترسی مبتنی بر نقشِ تأییدشده و آزمون تعارض و همگام‌سازی واقعی لازم است.
- محاسبه Weighted Progress / Roll-up و انتخاب روش محاسبه برای هر Objective هنوز اضافه نشده است.
- مدل کنونی هم‌راستایی هدف با رکن یا Objective کار می‌کند؛ Alignment مستقل با KPI/KR/Initiative طبق امکانات جدید Perdoo 3.0 هنوز توسعه نیافته است.
- ارکان تودرتو، سه نمای Cascade/Map/Board با یک فیلتر مشترک و مدیریت پیشرفته Timeline همچنان شکاف Functional Parity هستند.
- بخش آموزش از رابط عملیاتی مخفی شده، اما حذف فیزیکی کامل کد سازگاری قدیمی انجام نشده است.
- اطلاعات با داده‌های واقعی، فقط در صورت ثبت در همان فضای کاری کاربر، نمایش داده می‌شوند؛ داده ناقص با صفر عملکرد جایگزین نمی‌شود.
